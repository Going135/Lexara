# 框选中译英验收（2026-11-01）

## 范围

三份自建、非私人样本：网页文章、包含编号列表的真实 PDF、聊天气泡排版。网页和聊天样本在浏览器中实际渲染并截图，PDF 使用 Poppler 渲染。聊天样本用于复现气泡和折行，不代表已经在微信等聊天客户端完成实机验收。

OCR 使用随项目分发的 RapidOCR 1.2.3；识别文字发送至当前已配置的真实兼容模型服务。请求不携带截图、单词本、聊天记录或其他用户文档。模型服务地址和密钥不写入报告。

## 基线问题与处理

1. 网页标题与正文、PDF 编号列表被拼在一起：文字整理增加标题字号差异、列表标记和段落间隔判断。
2. 聊天气泡的第二行仅有「词。」时被英文行带裁剪遗漏：中文翻译改用整图检测。原来的高置信度长行不能证明短行没有漏字。
3. 模型在原文不完整时仍给出了流畅译文：低置信度行保留并标黄，等待用户核对后才发送；不再通过过滤把不确定文字直接删除。
4. 原流程完成后才显示译文：新增 SSE 流式响应、首段文字显示和分阶段计时；普通 JSON 响应仍可使用。

## 同组样本结果

字符错误率按编辑距离计算，忽略空白，包含标点。每组仅运行一次，不能代表总体准确率或速度分布；基线与复测的运行环境、冷启动状态不同，不据此宣称 OCR 加速。

- 网页译文保留标题与各段内容，「每天一篇文章」「三个新单词」「30/45 分钟」均保留。
- PDF 译文保留两项编号，复习日期 `1、3、7` 和 API 文字/截图说明正确。复测 OCR 漏了一个句末句号，仍属已知识别误差。
- 聊天样本找回「词。」短行，译文保留下午三点、图书馆、笔记本、阅读/复习安排和 45 分钟。`English reading` 的原文空格仍可能被 OCR 合并；字符错误率忽略空白，不能用 0% 表示排版完全无误。
- 译文语义人工检查通过这三份短样本，不代表长文、专业领域和全部模型均已验证。

## 回归与交付边界

翻译测试 24 项通过；相关回归 13 个文件全部通过，累计 306 个有计数的检查项，另有 OCR 线程检查通过。之后为打包运行库冲突新增 2 项守卫，打包测试共 7 项全部通过。覆盖英文识词、连续扫描、瞄准层、AI 辅助、人设、桌宠生命周期、桌面感应和打包守卫。Windows 模型配置加密测试另外 13 项通过。

打包验收发现当前工具 PATH 中的旧 libheif C++ 运行库和 Poppler 的同名 ICU 库被误收集到根目录。后者与 Qt 使用的 Windows ICU API 不兼容，导致 QtCore 找不到入口点。五个打包配置统一显式使用 PySide6 提供的 C++ 运行库，并排除误收集的 ICU，让 Qt 使用 Windows 自带实现；仅修改打包结果，不修改系统文件或 PATH。

打包后启动台检查通过，源码与安装包模块一致性检查通过。严格的安装包 OCR 样本验收尚未通过：离屏测试字体异常，显式指定字体目录后的复测超时。用户随后要求暂停打包，本轮不将现有 exe 作为已验收体验版交付；未继续生成或运行安装包。源码 OCR、真实模型和交互回归的通过结果不受此限制影响。

尚未覆盖：真实混合 DPI 多屏设备、复杂双栏 PDF、聊天客户端特殊字体、长文或专业术语的模型质量、服务商计费和限流压力测试。识别与翻译耗时在用户机器、选区大小和模型服务变化后可能明显不同。
