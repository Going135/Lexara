# 启动台原型 · 玻璃罐与交互面板

双击 `启动台.html` 即可运行（不需要 Python、不需要联网、不需要构建）。
这是**设计预览**，没有改动 `src/` 里的任何代码。

```
ui-preview/
├── 启动台.html          单文件原型（HTML + CSS + Canvas，零依赖）
├── jar_crack_01.png     轻微裂纹（整面玻璃的透明覆盖图，撞击点在正中）
├── jar_crack_02.png     中度裂纹（放射纹伸到半路 + 同心弧 + 碎玻璃亮点）
├── jar_crack_03.png     严重裂纹（放射纹打通到四边 + 密集蛛网 + 碎片）
├── make_cracks.py       三张裂纹图的生成脚本（Pillow，改参数可重出图）
└── _verify_gait.js      步态验证：_verify_gait.js / _verify_heading.js（node 直跑）
```

重出裂纹图：`python make_cracks.py`（Pillow 12.3.0 实测可跑）。
硬约定只有一条：**图尺寸 = 瓶身（`.jar-box`）的设计 CSS 尺寸 980×433，1:1**，
`.crack` 用 `object-fit:fill` 贴满瓶身，所以图里一个像素就是一 CSS 像素，
划痕不会被拉伸歪。第四轮起裂纹**铺满整面**（中间也是玻璃），
不再画成两条 3.2% 的竖带 —— 当年「竖带 ↔ 侧壁必须同比例」那条耦合随之解除，
但 `.stage` 的 `flex-basis` 一改，瓶身高度就变，`JAR_CSS_H` 要跟着改并重出三张图。
撞击点 `IMPACT=(0.500,0.440)` 和 `spawnDebris()` 里的 `b.width*.5, b.height*.44` 是一对，
改一边另一边必须同步，否则碎片会从别处崩出来。

## 二、蜘蛛是真移植，不是贴图

`crawler_spider.py` 的参数逐个搬过来：`BASE_SCALE 1.45`、`LEG_DEF`、
`STEP_FRAC .30 / URGENT .50 / OVER .92 / PLACE .85`、迈步时长 0.10~0.17s、
抬腿 18%、`LEAD_SECONDS .3 / LEAD_MAX_FRAC .3`、`REST_K .8`、
`THORAX 18×11 × THORAX_SCALE 1.25`；渲染照 `spider_painter.py`：
深色外描边 + 亮色内芯、膝/尖红点、腹部到髋部的连接线、随朝向旋转的头胸矩形。

验证脚本直接从 HTML 里取脚本段，node 直跑：

```
node _verify_gait.js 启动台.html        # 速度扫描：干净步态的上限在 0.32~0.34 之间
node _verify_heading.js 启动台.html     # 朝向符号对照（+motion vs -motion）
```

```
0.25~0.32 局部单位/帧 → 峰值同时迈步 4，同侧相邻违规 0，越界帧 0
0.34 以上            → 峰值 10、同侧相邻违规出现、腿被硬拉越界
```

## 三、两个值得回主仓库的结论

1. **速度符号**：`crawler_spider.py` 里 `velocity = -motion/dt`。
   局部坐标随身体一起平移，身体往右走时前瞻方向也应是 +x，
   取负会让**朝向指到屁股后面、落脚点亮落在身体后方**（倒着走）。
   对照验证：`node _verify_heading.js <脚本>` → 原符号 heading=180°（背向行进），
   取正后 heading=0°（=行进方向），前瞻 dx 由 −5.4 变 +5.4。
   crawler.js 里那个负号对应的是「滚动位移」语义，桌宠传的是「体心位移」，语义变了。
2. **罐内行走速度上限**：身体在局部坐标下超过约 **0.33 单位/帧**，腿追不上静止位，
   会退化成「十腿齐迈 + 硬拉越界」。原型按 0.30 留余量：
   `speed = 0.30 × 60 × unit`（px/s）。拖动/远距离位移如果要更快，
   需要的是**提高迈步频率或缩短迈步时长**，而不是放大 motion。

## 四、Liquid Glass 换肤（布局不变）

需求是「前端风格改成 Liquid Glass，布局不变」。按规范色板（`#1A1A1A` / `#4A4A4A` /
`#0066FF` / `#FFFFFF`）走**浅色玻璃**，只动皮：

| 旧（深色「微光」） | 新（Liquid Glass 浅色） |
| --- | --- |
| 深底 `#0f151c` + 青色辉光 `#2ee6d6` | 桌面 `#EDF1F6` + 两团缓慢形变的蓝/石墨色块（`.desk::before/::after`，`morph` 22~28s） |
| 窗口 `#121a22` 实色 | `rgba(255,255,255,.8→.62)` + `backdrop-filter:blur(28px) saturate(180%)`（第六节起：这块皮只留给标题栏和下半区面板，罐区透明） |
| 一级文字 `#d6f5f0` | `--ink #1A1A1A`（规范禁止纯黑，所以不是 `#000`） |
| 强调色 = 青 | 强调色 = `--accent #0066FF`；小尺寸实心控件（13px 的 OCR 分段按钮）另用同色相压深的 `--accent-deep #0052CC`，白字才够 4.5:1 |
| 圆角 16 / 14 / 11 / 9px 混用 | 基准 `--radius:12px`、卡片与按钮 `.75rem`、小控件 `--radius-sm:8px` |
| 字体 Segoe UI 一把梭 | 系统 UI 栈 + 数值/状态用 `--mono`（JetBrains Mono → 系统等宽兜底，不联网取字体） |
| `transition:.16s ease` | 进场 `fade + translateY(16px)` 480ms、行间 100ms 错峰；悬停 `scale(1.03)` + 阴影抬升 200ms；弹性曲线 `--spring:cubic-bezier(.34,1.32,.64,1)`（≈ 刚度 120 / 阻尼 20）。动画属性只有 `transform` / `opacity` |

规范里超出 CSS 常规表达的三条，落地方式：

- **虹彩描边**：`@property --ir{syntax:'<angle>'}` 让 `conic-gradient(from var(--ir))` 可动画，
  用双 `mask` + `mask-composite:exclude` 只留边缘那 1px，14s 转一圈（第六节起挂在 `.panel::before`，
  只绕有玻璃的下半区）。
- **色差**：`.win-title` 上 `-1px 0 蓝 / +1px 0 红` 的 `text-shadow`，罐内闪白外圈那圈蓝也是同一个意思。
- **减弱动效**：`@media (prefers-reduced-motion:reduce)` 关掉流体形变、虹彩旋转、错峰进场、
  悬停缩放和罐子抖动，只保留透明度。

三处**画布/图片**跟着换了皮（不然浅色底下会糊成一片）：

1. 裂纹图：`make_cracks.py` 出的是「深色描边 + 近白内芯」（原本配 `mix-blend-mode:screen` 在深底上发光）。
   浅色玻璃上改成 `filter:invert(1)` + `multiply`，内芯翻成深色线，`.crack.on` 的透明度收到 `.8`
   免得划痕变硬黑。图本身没重出。
2. 蜘蛛：`CS.C` 由「深底青蓝发光」翻成「白外壳 + 炭黑内芯」（`bodyFill #FFFFFF` 是 1.9 倍宽的托底描边，
   `leg #1A1A1A` 是内芯，关节和第四条腿用 `#0066FF`），`LEG_AURA` 换成规范色板内的蓝→石墨梯度。
   步态参数一个没动。
3. 碎片粒子：`#dff6ff/#8fd6e8` → `#4A4A4A/#8FB4D8`（浅底上白碎片看不见）。

**一处需要你拍板的冲突**：最初的启动台规范写的是「绿色大矩形部署按钮」，
而 Liquid Glass 的色板里没有绿色，你选了「完全按规范色（蓝+炭黑）」，所以部署按钮现在是蓝的。
想退回绿的只改一个 token：`--accent` 保持蓝色给控件，另把 `.deploy` 的
`background/border-color/box-shadow` 三行换回 `linear-gradient(180deg,#5cf0a0,#28c87a)` 那组即可；
「收回」状态仍按你这次的要求保持红色。

换肤后的实测（1060×720 设计尺寸）：面板 `scrollHeight-clientHeight = 0`（含进场动画进行中，
最后一行 `.foot` 改成只淡入 —— 它贴底边，下移 16px 会瞬间撑出 2px 滚动条）；
部署按钮 240×64；罐子 360×320；`.stage-tip` 与罐体间隙 144px；
部署→收回整轮跑通，落定后 10 个落脚点（8 腿 + 2 触肢）全部在罐内，console 无报错。

## 五、信息架构调整：主页收「收藏单词」，参数进「设置」

需求原话：**「把"识别参数"，最大识词，最小置信这三个功能放在设置里吧，就不放主页了，
主页再放一个"我的收藏单词"界面」**。

主页 `.panel` 现在的内容（第四轮：桌宠大小和显示开关**搬回主页**、学习范围扩到六行）：

1. 学习范围：六档，一档一个占整行的长矩形
2. 桌宠大小滑杆 + 三个显示开关（置顶 / 释义卡 / 跟随鼠标）—— 合并成一行放
3. **我的收藏**：标题 + 计数「10 词 · 今日待复习 5」+「全部 / 待复习」筛选 + 一行横向滚动的单词卡
4. 数据来源状态条
5. 首次使用提示 + 部署按钮（钉在面板底部，不参与滚动）

代价写在第六节「实测」里：瓶身抬到 64% 之后面板净高只有 243px，扣掉钉底的部署行只剩
**158px 可视**，而内容要 386px —— 所以面板改成「内容自己滚、部署行不动」，
`scrollHeight-clientHeight = 228`。这不是回归老 bug：以前溢出是把 `.data`/`.foot`
压扁（看着没滚动条其实内容被裁），现在滚动条可见（6px 细条）、底部 18px 渐隐提示还有内容，
主按钮永远够得着。

`.sheet-mask` 弹层（`role="dialog" aria-modal`）现在只剩识别侧的三项：
**识别引擎（OCR 分段）· 最大识词 · 最小置信度**；入口从「设置」两个字换成**齿轮图标**
（内联 SVG，`aria-label="设置"` + `title`，hover 转 45°，`prefers-reduced-motion` 下不转）。

单词条的做法：

- 卡片 = 词 + 复习徽标（今天 / 约 N 天后 / 已掌握）+ 中文释义 + 4 个小点表示走了几档间隔；
  实测 176×44，一行放不下的部分横向滚动，滚动条隐藏（`scrollbar-width:none` + `::-webkit-scrollbar{height:0}`），
  右端用 `mask-image` 渐隐提示还有内容。
- 复习规则按 `1 / 3 / 7 / 14 天`：`REVIEW_DAYS`，`isDue = stage<4 && due<=0`；
  点一下卡片记一次复习（`stage+1`、`due` 跳到下一档），徽标和点阵立刻变，计数随之减少。
- 当前筛选下没有词时切 `.as-empty`，换成规范里的虚线空态：「这一轮没有要复习的词 /
  到日子蜘蛛会自己跳到前台提醒」。
- 词表现在是写死的 10 条（原型不需要 SQLite）；真机对应 `words` 表的 `stage / next_review` 字段。

设置弹层的交互细节：入口是标题栏「设置」按钮（`aria-haspopup="dialog"` + `aria-expanded`）；
弹层节点放在 `.win` 的**外面**（当时 `.win` 有 `overflow:hidden` 会裁掉它；现在窗口不裁了，
但弹层要盖住整屏、还得自带遮罩，留在外面仍然更合适）；
打开时焦点给第一个可用分段按钮、关闭时还给来源按钮；Tab 在弹层首尾回绕；
Esc 优先关弹层（在全局 keydown 里排在「部署态 Esc 回启动台」之前）；点遮罩 / ✕ / 「完成」都关闭；
`beginDeploy()` 会先 `closeSheet()`，免得弹层盖在破罐动画上。滑杆和数字框改动即时写进
`localStorage["eightlegs.launcher"]`（实测：`max_words:8`、`min_conf:0.66`）。

顺手修掉一个真 bug：部署完成后收起启动台的那个 `hideTimer` 回调，守卫写的是
`if(phase!=="deployed"||launcher.style.display==="flex") return` —— 而启动时
`backToLauncher()` 已经把 `display` 写成了 `flex`，于是这个条件恒成立：
**部署后启动台永远不收起、右下角桌宠窗口从来不出现**（正常浏览器里必现，跟探针环境无关）。
现在只判 `phase!=="deployed"`：原本想防的「用户在 300ms 内点了回到启动台，别抢回去」
已经被 `backToLauncher()` 里的 `clearTimeout(hideTimer)` 覆盖了。修完实测：
部署 → 300ms 后 `display:none` + 桌宠出现 + 「回到启动台」按钮可见，再收回 → 罐内落定、
裂纹愈合、侧壁上沿亮边复位、按钮翻回「部 署」，第二轮部署同样跑通。

验证口径说明：in-app 浏览器在后台时 `visibilityState=hidden`，rAF 挂起、CSS 过渡读不到中间值，
所以布局尺寸一律用 `offsetWidth/offsetHeight`（不含 `scale(.99)` 进场缩放）测，
动画里程碑靠一份临时探针文件（虚拟 `performance.now` + `__pump(ms)` 推进 `jar.tick/fxDraw/timeline/recallTimeline`）跑，
探针文件验完已删，`启动台.html` 里只保留 `window.__dbg()` 自检钩子（本轮又加了
`jar.ground/reach/rect` 和十脚实际世界坐标 `feet`，用来当场证明「蜘蛛全在玻璃里」）。
换窗口尺寸量设计稿数值时，探针里要同时用 `!important` 压住 `max-height:800px` 那条媒体查询，
否则 `.stage` 会被收到 58%、量到的不是设计尺寸。

## 六、上半区改成「圆柱玻璃瓶的正视图」（四轮收敛）

需求四轮，每轮都是**理解纠偏**而不是调色：

1. **「这是我设想的页面布局，中间的玻璃罐两边无边框无填充，透明」** → 罐区去玻璃皮。
2. **「这不对，两边应该有个玻璃框，而且中间的盖子可以不要了，对应的，三个玻璃损毁贴图也要适应新的玻璃框」**
   → 补两条玻璃侧壁、删盖子/罐口、裂纹图重画。
3. **「这本质上是一个圆柱玻璃瓶子的正视图：上面那个界面是盖子，下面那个界面是瓶身的标签
   （所以看着是矩形），所以两侧的玻璃板延长到与上下两个界面垂直，两个玻璃板移动距离大一点」**
   → 整窗读成一个瓶子：`.titlebar` = 盖子、`.panel` = 标签、中间透明区 = 瓶身。
4. **「上下比例往线框图那种 64:36 靠；桌宠大小 + 三个显示开关搬回主界面；中间其实也是玻璃，
   所以裂纹贴图改到屏幕中间、整面加一点磨砂让里面的蜘蛛发虚；学习范围改成六个占整行的长矩形；
   设置按钮改齿轮图标；部署两个字大一点」** → 本节末尾的「第四轮」+ 第五节的信息架构改动。

### 瓶身几何（第三轮）

- `.jar-box`：`width:min(980px,94%)` × `height:100%`、`bottom:0` —— 从原来的
  `min(360px,46%) × min(340px,82%)`、`bottom:6%` 改成**顶天立地 + 挪宽**。
  1060×720 下实测：瓶身 980×392，上沿与 `.titlebar` 下沿间隙 **0**、下沿与 `.panel` 上沿间隙 **0**
  （这就是「与上下两个界面垂直」），左右各留 40px 空气（`.stage` 1060 宽）。
- `.glass-wall`：`width:var(--wall)`（`--wall:3.2%`，设计宽下 **31.4px**）、`top:0;bottom:0`、
  **没有上下圆角**，`border-top:0;border-bottom:0` —— 只画左右两条描边，上下交给盖子/标签的边线，
  接缝才干净。壁宽写成百分比而不是定值：裂纹图 `object-fit:fill` 铺满瓶身，
  图上那条不透明竖带就是「瓶宽的 3.2%」，只有同比例缩放两者才不会脱开（上一版写死 22px 就有这个隐患）。
- `.glass-wall::after`：壁顶那圈 2px 亮边 = 盖子底下的**罐口缝**（第二轮删掉 `.jar-lid` 后由它顶替
  「罐口还在不在」这一拍）：`jarBox.classList.add("opened")` 时淡出、收回落定（620ms）后回来。
  `opened` 状态位和 `__dbg().jarDom.opened` 都保留，语义没变。瓶身上下现在顶天立地，
  所以这圈亮边的位置也从「罐口」变成「盖子与瓶身的接缝」，读起来仍然对。
- `.glass-inner`（瓶底）：圆柱底面在正视图里是又扁又宽的椭圆 → `left/right:var(--wall)`（收到侧壁内沿）、
  `bottom:0`、`height:13%`，紧贴标签上沿。
- `.jar-flash`：`inset:-8%` → `inset:0`，上下被盖子/标签挡住，再外扩只会被 `.stage` 裁掉。
- `.stage-tip`：从左下角挪到**左上角 `.stage-tag` 底下**（`top:34px`）。瓶身铺满上半区后没有「玻璃外」
  的位置了，左下会被蜘蛛的脚扫到（实测十脚纵向覆盖罐高 33%~83%），左上角是唯一的空区。

### 蜘蛛跟着瓶子长大（这次动了几个派生量）

`layout()` 的公式一行没改（`unit=unitForWidth(min(w*.52,h*.62))`、`lo/hi=.30/.70`、
`speed=0.30×60×unit`），但因为瓶身变高，**min() 的限制项从宽换成了高**，此后每抬高一次
`.stage` 的比例，蜘蛛就再大一圈：

| | 旧（360×340 罐） | 第三轮（980×392） | 现在（980×433） |
| --- | --- | --- | --- |
| `unit` | 0.640（由 `w×.52` 定） | 0.831（由 `h×.62` 定） | **0.908**（仍由 `h×.62` 定） |
| 腿可达半径（REST_K 后） | 93px | 121px | **133px** |
| `lo/hi` | 108 / 252（跨 144px） | 294 / 686 | **294 / 686**（跨 392px，与瓶宽同比） |
| 像素速度 | 11.5 px/s | 15.0 px/s | **16.35 px/s**（局部单位速度没变，还是 0.30 单位/帧） |
| 地面线 `ground` | 197（`h×.58`） | 227（`h×.58`） | **248**（`h×.58`） |

`lo/hi` 只由瓶宽定，瓶宽没变（仍是 `min(980px,94%)`），所以第三轮到第四行不变 —— 变的只有
`unit`（瓶高）和 `ground`（瓶高）。

两处新增的保护：

- `ground` 改成 `min(h*.58, h - reach - h*.03)`：瓶子矮到一定程度时，下缘那几条脚会踩到标签上沿
  （= 瓶底），这行留不出余量就自动把地面线抬上去。设计尺寸下 `248 < 433-133-13=287`，
  取的还是 `.58h`，也就是说**当前不 binding**，只是给矮屏（`max-height:800px` 那条把 `.stage` 收到 58%）
  兜底。
- `returnIn()` 的落点从 `ground-h*.62`（旧罐子是 +52px 的罐口上方）改成
  `max(ground-h*.62, h*.04)`：瓶身现在顶到盖子底下，按老公式会从窗口外落进来
  （表现为「凭空出现」），收到瓶口内侧那一圈。瓶身抬到 64% 之后 `248-268 < 0`，
  **这个 clamp 现在是真正生效的那一项**（探针里起始 `y≈16`），Spider 从盖子接缝下方
  加速落到 `ground 248`，方向对了。

**代价说清楚**：`GAIT_MAX_LOCAL_PER_FRAME=.30` 是局部单位，放大瓶子只放大像素速度、步态依旧成立
（10 条腿照样追得上静止位）。行走带还是 392px（瓶宽没动），但速度从第三轮的 15.0 涨到 16.35，
**单趟由 ~12.5s → ~26s → 现在 ~24s** —— 看着比最初那版「慢爬」得多。嫌慢有两条路：把带子收到
`.40/.60`（一趟约 12s），或者把 `lo/hi` 保持、把 `.30` 降到 `0.24` 反而更慢 —— 所以真要提速只能收带子，
别动 0.30（那是实测上限）。

### 第四轮：瓶身抬到 64%、整面磨砂、裂纹铺满正面

  「pet_scale 与三个显示开关在主界面」。

### 裂纹图（`make_cracks.py`，现在是这样）

第二、三轮的图只画在两条窄壁上（那时中间不算玻璃）；第四轮起整面都是玻璃，
所以图回到「以撞击点为中心的蛛网」，但**只在图内画、出边即停**，不会再有浮在空气里的划痕：

- 约定：`.crack` 是 `inset:0;object-fit:fill` 贴在 `.jar-box` 上 → **图的比例坐标 = 瓶身比例坐标**，
  且图尺寸 = 瓶身设计尺寸 **980×433（1:1）**。第二轮那种「图 900×640 ↔ 罐宽 360」的
  各向异性映射（横 2.5×、竖 1.88×）已经废弃 —— 它会把划痕拉歪。
- 放射纹的长度用「沿该方向到玻璃边缘的距离」的分数控制（01 `0.10~0.26`、02 `0.26~0.62`、
  03 `0.55~1.00`），不用绝对像素：窗口比例变了、重出图之后「裂到哪」还是同一个观感。
  三档只加内容不挪旧内容，所以动画里三张图叠着看不冲突。
- 画法：长直段 + 每 4 步一次折角（`ang ± 0.22~0.46`），抖动 `wob` 每档 0.14/0.16/0.18。
  早先 `wob=0.30` 无折角，出来像一束意大利面；同心弧的角跨度也从 `0.5~2.1` 收到
  `0.4~1.6`（跨太大就画成闭合圈，不像裂的）。最重一档才有碎玻璃亮点和撞击点那撮「破口」。
- 踩过的坑：`step *= rng.uniform(...)` 是几何衰减，只靠 `walked < length` 判断会在原地打转，
  第一次跑就卡死。现在有 `guard < 400` 硬上限 + `step` 下限 2.6。
- 颜色沿用旧约定（暗底描边 + 近白内芯），HTML 里还是 `filter:invert(1)` + `multiply`；
  `.crack.on` 的透明度从 `.85` 降到 **`.72`** —— 整面都裂的时候 `.85` 会把瓶身压成一张磨砂贴纸。
- **线宽是每档一个显式 `stroke`（1 / 1 / 2）**，最轻的一档必须不粗于后面的档。
  曾经写成 `4 - branch_depth`，结果最轻的一档反而最粗，窄壁上糊成一坨。
  三档的轻重靠「条数 + 长度 + 分支」拉开，不靠线宽。

数值校验过（numpy）：三张图 980×433 RGBA（**2.9KB / 8.5KB / 28KB**），墨迹像素
1090 → 7787 → 29878（严格递增），离撞击点的最远半径 87 → 234 → 460（03 打通到四边），
01 只在中心 20% 高度的一小簇、02 覆盖到半分面、03 满幅。

### 实测（探针页强制 1060×720 + `.stage{flex:0 0 64%!important}`，因为 in-app 视口只有 530×625）

必须先骗过媒体查询：530×625 会命中 `@media (max-height:800px)`，那条把 `.stage` 收到 58%，
探针只加 `flex:0 0 64%` 不加 `!important` 的话量出来全是矮屏值（上一轮就这么被坑过一次）。
另外 `getBoundingClientRect()` 比布局值小 1%，因为 `.win` 进场带 `.99` 缩放 ——
读尺寸一律用 `offsetWidth/offsetHeight`。

布局：`.stage` **432.6** / `.panel` **243.4**（44px 标题栏 + 432.6 + 243.4 = 720）；
`.jar-box` **980×432.6**，与盖子、标签的上下间隙 **0 / 0**，左右各 39.6；
两条 `.glass-wall` 宽 **31.04**（`--wall:3.2%`），无上下圆角；`.crack` 三张与 `.jar-box`
**逐边对齐**（dx/dy/dw/dh 全 0），`.glass-face` 同一矩形 —— 磨砂面和裂纹图必须同边，
否则裂到玻璃外。层序按 z-index 复述一遍：canvas 1 → frost 2 → 瓶底 3 → 壁 4 → 裂纹 5 → fx 6 → flash 7；
`.jar-lid/.jar-neck/.glass-back/.glass-front/.jar-shadow` 节点数仍为 **0**。

蜘蛛：`__dbg()` 里 `unit 0.908 / speed 16.35 / lo-hi 291-679（含 .99） / ground 248 / reach 133`，
行走中十脚世界坐标 `x∈[353,614]`、`y∈[131.5,361.2]`（瓶宽 980、瓶高 433）
→ 横向全在两条壁之间（壁内沿 31 / 949），纵向占 30%~83%，最下那只脚离标签上沿还剩 **72px**。

面板容量：`.panel` 243、钉底 `.foot` 84 → **可视 158**，而 `.panel-scroll` 的
`scrollHeight` 是 **386**（六行学习范围 `27.55`×6=165 + 标题行 + 桌宠大小/显示那行 + 收藏单词 + 数据行），
**超出 228px**。六行长矩形、滑块行、收藏列表都是这一轮按要求搬进来的，所以滚动是内容决定的，
不是比例决定的 —— 就算退回 58:42，面板净高 284 装 386 一样要滚（那时超出 ~102px）。

交互全跑通：`部 署` → 三档裂纹 0/180/420 + 抖动 + 碎片从 `(0.5, 0.44)` 崩出 → 620ms `burstOut`+白闪
→ 740ms `deployed`（`opened`、`fade`、按钮翻成红色「收 回」）→ 真实 300ms 后 `display:none` + 桌宠出现 →
`← 回到启动台` → 启动台回来、瓶身是**裂着的空罐**（`fade:false`、`opened:true`、cracks 全 on）→
`收 回` → 闪白、蜘蛛从 `y≈16`（瓶口内侧，clamp 生效）落到 `ground 248`、裂纹 3→2→1 愈合、
620ms 上沿亮边复位、`phase` 回 `idle`、`stepping:2`（阈值步态恢复）、按钮翻回 `部 署`。
齿轮 → 三行弹层开/关正常；`petScale=1.45`、`follow_mouse`、`selected_mode:"ky"`（新增的考研档可选）
都落进了 `localStorage`；磨砂层不吞点击（瓶身正中 `elementFromPoint` 命中 `#spiderCanvas`）；
console 无报错，收尾把 `localStorage` 清回 `null`。

探针自己的坑记一条：`requestAnimationFrame` 的替换版必须用**队列**不能只存一个回调 ——
`backToLauncher()` 会另外排一次 rAF，单回调变量会把主循环覆盖掉，表现为「收回卡住在 recalling、
裂纹不愈合」。这是探针的 bug，别当成产品 bug 去改产品代码。

**没验证到的一项**：in-app 浏览器在后台时 `take_screenshot` 直接失败
（`NATIVE_BROWSER_VIEWPORT_UNAVAILABLE … visibilityState=hidden`），所以这轮的四件事**只做了数值和离线
像素核对，没有肉眼看过整页**：3.4px 磨砂把蜘蛛糊到什么程度（够不够「隔着玻璃」又没糊没）、
整面裂纹在 `.72` 下压不压得过浅底、六行长矩形会不会显得比原来那排方块「表单化」、
以及瓶身 64% 之后盖子/标签读不读得成「一个瓶子」。离线 composite 只能看裂纹图和瓶底的重叠关系
（`_look_face.png` / `_look_sev.png` 已删，`make_cracks.py` 可随时重出），面板排版和磨砂观感得把窗口
切到前台扫一眼才知道要微调哪头。

**唯一还没定的**：64:36 之下面板必须滚动。三个选项 ——(a) 就这样滚（部署行钉底，收藏列表跟着滚）；
(b) 回到 58:42，蜘蛛小一圈（`unit 0.908→0.823`），面板净高 284，仍要滚但只滚 102px；
(c) 保持 64%，把「我的收藏单词」和底部数据行挪出面板（例如收进齿轮弹层），主页就只剩
学习范围 + 桌宠大小 + 显示开关，净高 243 勉强不用滚。我按 (a) 做了，因为 (c) 会把上一轮
「收藏单词放主页」的要求撤掉。

## 七、往真机移植

- **PySide6 路线**：**启动台窗口整窗要 `WA_TranslucentBackground`**（瓶身透明之后，
  没有它那块就是黑的或实色的），标题栏（盖子）和面板（标签）各画一块半透明白渐变，
  瓶身那块只画**两条侧壁 + 底面椭圆**（`QPainter` 画带渐变的窄 `QRectF` + 一条扁椭圆），
  其余什么都不画 —— 「透明」在 Qt 里是「不绘制」而不是「设个 alpha」；
  侧壁宽度按瓶身宽的 **3.2%** 算（`int(body.width()*0.032)`），不要写死 31px；
  `.jar-box` 的七层（画布 / 磨砂 / 瓶底椭圆 / 左右壁 / 三张裂纹 / 碎片 / 白闪）
  → 一个 `QWidget` + `QPainter` 按 `paintEvent` 里的先后顺序画，顺序就是那串 z-index，别倒过来；
  裂纹用三张整面 `QPixmap`（`scaled(rect, IgnoreAspectRatio)` 或直接 drawPixmap 铺满瓶身矩形）
  叠着画，**现在图和侧壁没有比例耦合了**（第四轮起图铺满整面），所以换窗口尺寸不必重出图，
  只要保证 draw 的目标矩形 = 瓶身矩形 = `.glass-face` 矩形；
  白闪 → 全屏 `QWidget`（`Qt.FramelessWindowHint | Qt.WindowStaysOnTopHint | Qt.Tool` +
  `WA_TranslucentBackground`），`QPropertyAnimation("windowOpacity")`，
  `setAttribute(Qt.WA_TransparentForMouseEvents)` 保证不吞点击；
  时间轴 → `QSequentialAnimationGroup` 或 `QTimer.singleShot` 五档；
  **收回**是同一条时间轴的反向：白闪做成贴在罐子上的小 `QWidget`（而不是全屏），
  蜘蛛用一段 `y = top + (ground-top)·u²` 的加速下落喂给 `Spider.update()`，
  裂纹按 3→2→1 的顺序淡出；按钮只是同一颗 `QPushButton` 换 QSS（蓝 ↔ 红）；
  浅色玻璃在 Qt 里没有 `backdrop-filter`，用半透明白 `QGraphicsOpacityEffect` /
  直接铺一层带 alpha 的渐变 + `WA_TranslucentBackground` 近似，虹彩描边可以省；
  **「蜘蛛隔着玻璃发虚」这条要单独实现**：`backdrop-filter:blur(3.4px)` 在 Qt 没有对应物，
  要么把 spider 画进一张 `QImage` 后 `QGraphicsBlurEffect(3.4)` 再 drawImage（最接近），
  要么干脆用 `smooth` 降采样到 1/3 再放大回去（便宜、效果粗）；
  千万别对整个窗口做模糊 —— 浏览器的实现因为 `.jar-box` 是 backdrop root，只糊得到瓶身内部，
  桌面是不糊的，Qt 里全糊会直接毁掉第一轮要的「透明」；
  面板 → 把 `dialogs.py` 的 QSS 抽出来复用，控件一一对应；**`.panel` 必须是
  `QScrollArea(setWidgetResizable=True)` + 外侧一个不滚的部署行**（`QVBoxLayout` 里
  scroll 用 `Stretch`、按钮行 `Minimum`），因为 64:36 之下内容实测 386px、可视只有 158px，
  不滚就装不下这轮搬进来的六行 + 滑块行 + 收藏列表；
  学习范围六行 → 六颗 `QRadioButton` 或自绘 delegate，`sizePolicy` 横向 `Expanding`、
  纵向 `Fixed`，每行 24~28px：名称在左、`monospace` 词数靠右、选中标点在右端 11px 处，
  **不要**再用网格里的正方形按钮；
  「设置」入口 → 一颗 28×28 无边框 `QPushButton`，图标用 `QStyle.StandardPixmap.SP_FileDialogContentsView`
  之类并不像齿轮，直接 `QSvgRenderer` 画原型里那段 8 齿描边 SVG（`viewBox 0 0 24 24`、
  `stroke-width 1.9`）最稳，hover 旋转用 `QPropertyAnimation("rotation")` 包一个 `QGraphicsRotation`；
  「设置」弹层 → 一个 `QDialog`（`exec()` 模态即可，`QFormLayout` **三行**（识别引擎 / 最大识词 /
  最小置信度）+ 底部按钮盒，桌宠大小和三个显示开关已经在主页上，别再往弹层塞），
  主页 `.words-list` 那条横向滚动 → `QListView` + 横向 `QBoxLayout` 或 `QScrollArea(setWidgetResizable)`，
  徽标和点阵用 delegate 画，别塞五个 `QLabel`；
